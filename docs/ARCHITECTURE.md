# フォルダ構造設計思想

## 概要

100個のゲームを効率的に管理・開発するため、**ハイブリッド型アーキテクチャ**を採用しています。

これは以下2つの優れた設計パターンを組み合わせたものです：
- **案1: ゲーム番号別（シンプル・管理性重視）**
- **案10: ハイブリッド構造（拡張性・再利用性重視）**

---

## 採用した設計パターン

### パターン1: ゲーム番号制（001～100）

**概要:** 各ゲームに連番を振り、`001-2048`, `002-snake` のように名前付けする

**メリット:**
- シンプルで分かりやすい
- ソート順序が自動的に適用される
- 新ゲーム追加時の命名ルールが明確
- 進行状況が一目で分かる

**実装例:**
```
games/001-2048/
games/002-snake/
games/003-flappy-bird/
...
games/100-final-game/
```

### パターン2: ハイブリッド構造（共有リソース + 独立ゲーム）

**概要:** 共有リソース（CSS, ユーティリティ関数）と独立したゲーム環境を分離

**メリット:**
- コード重複を削減
- 共通スタイルで統一感を維持
- スケーラビリティが高い
- 保守性が向上

## 各ディレクトリの役割と責任

### 📁 `/` (ルートディレクトリ)

**用途:** プロジェクト全体のエントリーポイント

**重要ファイル:**
- `launcher.html` - ユーザーが最初にアクセスするページ
- `README.md` - プロジェクト説明とクイックスタート

**設計理由:** ユーザーが開くファイルを明確にするため

---

### 📁 `/games/`

**用途:** すべてのゲームを管理するディレクトリ

**特徴:**
- 各ゲームは独立した`XXX-gamename/`フォルダで管理
- 番号は001～100の3桁ゼロパディング
- 独立性を保つため、各ゲームは自力で動作可能

**ゲーム追加時のプロセス:**
```
1. フォルダ作成: games/002-snake/
2. ファイル作成: index.html, game.js, styles.css
3. launcher.js に登録
4. launcher.htmlで確認
```

**設計理由:**
- 100個のゲームが扱えるようにスケール設計
- 各ゲームの独立性を保証
- 番号付けで管理しやすい

---

### 📁 `/shared/`

**用途:** すべてのゲーム間で共有するリソース

**サブディレクトリ:**

#### `/shared/styles/common.css`
すべてのゲームで共通して使用するスタイル

**含まれるクラス:**
- `.game-container` - ゲームの基本レイアウト
- `.game-header`, `.game-title` - ヘッダー関連
- `.btn`, `.btn-secondary` - ボタンスタイル
- `.modal-overlay`, `.modal` - モーダルUI
- `.score-board`, `.score-item` - スコア表示

**メリット:**
- ゲーム開発時にCSSをゼロから書く必要がない
- 全ゲーム間で統一感を保つ
- ブランディング変更が一元管理可能
- ファイルサイズを削減

#### `/shared/utils/gameUtils.js`
すべてのゲームで使用できるユーティリティ関数

**提供される機能:**

1. **GameStorage** - ローカルストレージ操作
   ```javascript
   GameStorage.setScore(gameId, score)
   GameStorage.getScore(gameId)
   GameStorage.setBestScore(gameId, score)
   GameStorage.getBestScore(gameId)
   ```

2. **GameModal** - UI モーダル
   ```javascript
   GameModal.show(title, message, onOk)
   GameModal.confirm(title, message, onYes, onNo)
   ```

3. **GameStats** - ゲーム統計
   ```javascript
   GameStats.recordGame(gameId, data)
   GameStats.getStats(gameId)
   ```

4. **DeviceDetect** - デバイス判定
   ```javascript
   DeviceDetect.isMobile()
   DeviceDetect.isTablet()
   DeviceDetect.isDesktop()
   ```

5. **GameAnimation** - アニメーション補助
   ```javascript
   GameAnimation.fadeIn(element, duration)
   GameAnimation.popIn(element, duration)
   ```

**メリット:**
- ゲーム開発が高速化
- スコア保存、モーダル表示などの共通処理が統一
- デバイス別対応が簡単

#### `/shared/assets/`
将来用の画像、音声、フォント保存ディレクトリ

**用途例:**
- `images/` - アイコン、背景画像
- `sounds/` - BGM、SE
- `fonts/` - カスタムフォント

## 設計上の重要な決定

### 1. 共有リソースの配置（`/shared/`）

**選択肢:**
- A) 各ゲームフォルダに共有リソースをコピー
- B) **ルート直下の `/shared/` に一元化** ← 採用

**理由:**
- DRY原則（Don't Repeat Yourself）を遵守
- メンテナンスが容易
- ブランディング更新が一括対応可能
- ファイル管理がシンプル

---

### 2. ゲーム番号制の採用

**選択肢:**
- A) ジャンル別分類（puzzle/, action/ など）
- B) **ゲーム番号制（001, 002, 003...）** ← 採用

**理由:**
- ジャンル判定が不要（作成者が判断する負担が少ない）
- 進行状況が一目瞭然
- フォルダソートが自然
- 100個という目標数が明確

---

### 3. ハイブリッド構造の採用

**選択肢:**
- A) 単一ファイル型（すべてのゲームを1つのHTMLで管理）
- B) 完全独立型（各ゲームが完全に独立）
- C) **ハイブリッド型（共有リソース + 独立ゲーム）** ← 採用

**理由:**
- ユーザー体験の統一感
- 開発効率の向上
- スケーラビリティ
- 保守性のバランス

---

### 4. ランチャーページの必須化

**役割:**
- ユーザーのエントリーポイント
- ゲーム一覧表示
- ゲーム進行状況の視覚化

**技術実装:**
- 動的なゲームカード生成（launcher.js）
- 共有スタイルの活用（launcher-styles.css）
- レスポンシブデザイン対応

## 開発フロー

### 新しいゲームを追加する際の流れ

```
1. フォルダ作成
   mkdir -p games/002-snake

2. 基本ファイル作成
   - index.html（共有cssをインポート）
   - game.js（共有utilsをインポート）
   - styles.css（ゲーム固有のスタイルのみ）

3. launcher.js に登録
   GAMES_LIST に以下を追加:
   {
       id: '002-snake',
       number: 2,
       name: 'Snake',
       emoji: '🐍',
       description: 'Classic snake game',
       path: 'games/002-snake/',
       status: 'available'
   }

4. ローカルテスト
   python3 -m http.server 8000
   launcher.htmlで確認

5. Git コミット＆プッシュ
   git add games/002-snake/
   git commit -m "Add game 002: Snake"
   git push -u origin claude/create-fun-game-XXX
```

## パフォーマンス考慮事項

### 読み込み速度最適化

1. **共有リソースのキャッシング**
   - common.css と gameUtils.js がブラウザキャッシュに保存される
   - 2個目以降のゲームは高速読み込み

2. **ゲーム独立性**
   - 各ゲームは独立して読み込める
   - 不要なリソースを読み込まない

3. **LocalStorage活用**
   - スコアをDBではなくローカルに保存
   - サーバー通信なし

---

## セキュリティ考慮事項

1. **クライアント側処理のみ**
   - サーバー通信なし
   - XSS脆弱性を回避（ユーザー入力なし）
   - CSRF脆弱性なし

2. **LocalStorage のデータ**
   - パスワードなどの機密情報は保存しない
   - ゲームスコアなどの非機密情報のみ

3. **API 呼び出しを追加する場合**
   - サーバー側でバリデーション
   - CORS対応
   - リクエスト検証

## 保守ガイドライン

### 共有リソース更新時

```
1. common.css を更新
   → すべてのゲームに反映（自動）

2. gameUtils.js を更新
   → すべてのゲームで使用可能

3. launcher.html を更新
   → 次のゲーム追加時に新機能が適用
```

### 個別ゲーム維持

```
1. ゲーム内容の変更
   → そのゲームのファイルのみ修正

2. ゲーム削除
   → games/XXX-gamename/フォルダ削除
   → launcher.js から削除
```

## トラブルシューティング

### 共有リソースが読み込まれない

**問題:** ゲームのスタイルが反映されない

**解決:**
```html
<!-- 相対パスの確認 -->
<link rel="stylesheet" href="../../shared/styles/common.css">
```

### ゲームが重い

**チェック項目:**
1. DOM操作の数を削減
2. requestAnimationFrame の使用
3. 画像最適化
4. イベントリスナーの削除

### LocalStorage 容量超過

**解決:**
- GameStats は最新100レコードのみ保存
- 不要なゲームデータはクリア
